# 团队知识与文档关系

文档支撑协作，不是协作的全部。目录不要求各项目一致，但事实归属和读取路径必须明确。

| 载体 | 负责什么 | 不承担什么 |
|---|---|---|
| AGENTS | 项目采用的规则、职责和授权边界；局部文件补充模块约定 | 日常进度和任务流水账 |
| README／文档总入口 | 当前简要基线、按任务必读清单、文档登记与直达链接 | 复制每个领域的详细结论 |
| 产品需求／路线图 | 目标、范围、规划与已发生成果 | 推测代码或发布已经完成 |
| 技术、设计、法律、数据库资料 | 对应领域的当前事实与依据 | 替其他领域作结论 |
| 验收记录 | 验证结果、时间、范围和未验证项 | 把候选方案当作完成证据 |
| 发布／执行记录 | 实际部署和数据库执行结果 | 把准备好的包或 SQL 当作执行成功 |
| CHANGELOG | 项目共用的真实变更账本 | 完整操作日志或第二份验收清单 |
| 历史／必要交接 | 追溯及未完成任务接续 | 日常现行依据的替代品 |

## 防漏读与防冲突

- 入口按任务列必读文件和适用条件，尽量直接到具体章节；避免连续跳过多份目录才到正文。
- 同一事实只维护一处。需要概览时保留短标签与证据链接，避免再写一整份状态。自动生成摘要应说明来源，不允许独立编辑成第二套结论。
- 专业文档标明维护方、适用范围、状态、最后核验及替代关系。真实状态未核验时明确写未核验，不以更新时间制造可信度。
- 历史与当前区分；已完成历史不为精简而删除。法律原文、执行过的 SQL 以及工具依赖文件不为目录整齐随意移动。
- 发现重复结论时先选定事实归属，再将其他位置改为引用；未经授权不批量归档或重构。
- 检查引用可达、登记齐全、状态明确、共享写入未覆盖他人。链接检查不能证明内容正确，也不能证明其他会话已经读懂。

## 阅读路由示例

| 任务 | 必读范围 |
|---|---|
| 页面改动 | 当前需求、模块规则、相关确认稿 |
| 接口变更 | 当前接口、兼容要求；涉及数据语义再读数据库基线 |
| 授权弹窗 | 当前实现、适用协议与审查结论；涉及存储再读数据约定 |
| 发布准备 | 当前交付物与发布步骤、实际部署记录；涉及迁移再读执行基线 |
| 判断是否完成 | 对应验收或发布证据，不只读 CHANGELOG |
